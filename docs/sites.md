# 来源站公示与核验记录

本文公示 bagaoji 所调查过的来源站状态，并说明**每个结论是怎么得出来的**。

两条写在前面的原则：

1. **公示的是可用性真相，不是功能宣传。** 七家里当前真正能直接用的只有两家，
   剩下的我们如实标出卡点性质，而不是含糊地说"支持"。
2. **只描述接口形态，不提供实现。** 本文不含任何加密密钥、签名算法实现或绕过方法。
   需要那部分内容的请自行评估合规风险。

所有结论均来自对**公开前端页面**的静态分析 + 真实请求验证，不是文档转述。

## 0.1 一键复现

```bash
python3 -m bagaoji --diagnose           # 刷新本表（GET 各站公开首页，不登录不解析）
python3 -m bagaoji --diagnose --json    # 结构化输出
```

自检只做一件事：GET 公开首页，记录 HTTP 状态，并在页面里检索停机声明关键字。

## 1. 小红书（内置适配器）✅

- 官网：<https://www.xiaohongshu.com/>
- 定位：本项目唯一内置来源
- 链路：短链 → `xsec_token` → 笔记页 → 内嵌 JSON

### 1.1 接口形态

| 用途 | 方式 |
|---|---|
| 短链展开 | 跟随 302 跳转（4 个短链域名） |
| 笔记数据 | 笔记页 HTML 内嵌的序列化状态对象（键名 `noteData`） |

无独立 API。数据在服务端渲染进页面，因此需要**移动端 UA**。

### 1.2 三条硬性约束

| 约束 | 不遵守的后果 |
|---|---|
| 链接必须带 `xsec_token` | 返回空骨架页，不同笔记 ID 的页面字节数完全一致，数据键不存在 |
| 需覆盖 4 个短链域名 | `.cn` / `.com` 混用时，缺失的那个会**静默失败**（HTTP 200 但无内容） |
| 必须用移动端 UA | 桌面 UA 拿到的 HTML 里不含笔记数据 |

### 1.3 图片直链

`fileId` 直接拼图床域名即可，**不需要签名、长期有效**。
页面上另有一套带签名的临时地址（含日期与哈希段），会过期，仅作兜底。

同一张 1242×1660 实测三档：`raw` 823 KB / `jpg` 88 KB / `webp` 53 KB。

### 1.4 已知不稳定点

视频直链**偶发 403**（同一签名 URL 前一次被拒、紧接着重试即成功；签名有效期实测约 3 天）。
内置退避重试 + 备用域名切换后，正常无需人工干预。

## 2. 抖虫 dousnap.com ✅（可用）

- 官网：<https://www.dousnap.com/>
- 定位：视频转文字 + 无水印下载 + AI 摘要/改写/封面生成
- 宣传支持：抖音、小红书、快手、B站、视频号、TikTok、YouTube
- 技术栈：Nuxt 3

### 2.1 接口形态

基址 `https://www.dousnap.com/prod-api`

| 用途 | 方法 | 路径 |
|---|---|---|
| 链接解析（元信息 + 直链） | POST | `/link/parse` |
| 创建转写任务 | POST | `/transcript/doTask` |
| 查询任务 | GET | `/transcript/queryTask?taskId=<id>` |
| 视频仿写 | POST | `/video/copy/createTask` → `/video/copy/detail` |
| 图集 OCR | POST | `/transcript/image/ocr/doTask` → `/queryTask` |
| 封面生成 | POST | `/cover/createTask` → `/cover/queryTask` |
| 文件上传转写 | POST | `/common/uploadVideo` / `/common/uploadAudio` |

### 2.2 形态要点

- 解析接口的请求体字段名是 **`text`**（不是 `url` / `workUrl`）——传错会报「文本内容不能为空」。
- **POST 请求体与全部响应体整体加密**（对称加密，密钥硬编码在前端 bundle 中，
  本仓库**不提供**）；GET 的普通查询参数不加密。
- 页面运行时配置声明 `turnstileEnabled: false`，当前不需要人机验证令牌。
  若将来变为 `true`，则需在请求头携带验证令牌，而该值只能由浏览器产出。

### 2.3 卡点

免登录按 **IP** 限流，实测约 2 条作品触发「免登录使用次数已达上限」。

**关键区分**：该额度**只作用于转写（ASR）**，不影响链接解析与下载。
也就是说"只要原片不要文案"这条路径基本不会被额度卡住；换出口 IP 也能重置额度。

## 3. 考拉解析 kaolajiexi.cn ⚠️（需登录）

- 官网：<https://bilibili.kaolajiexi.cn/>（按平台分子域）
- 同一套程序部署在 `kaolajiexi.cn` 与 `zanqianba.com` 两个主域
- 技术栈：服务端模板 + Vue2 + jQuery

### 3.1 平台子域实测

| 状态 | 子域 |
|---|---|
| ✅ 正常部署 | `www`、`bilibili`、`douyin`、`xiaohongshu`、`kuaishou`、`weibo`、`weishi`、`meipai`、`xigua`、`tiktok`、`instagram`、`twitter`、`facebook`、`acfun`、`youku` |
| ❌ 未部署（返回服务器默认页） | `shipinhao`、`youtube`、`miaopai`、`toutiao`、`music`、`zhihu`、`qq`、`sohu` 等 |

注意：页面宣传支持视频号与 YouTube，但这两个子域**并未部署**，宣传与实际不符。

### 3.2 接口形态

| 用途 | 方法 | 路径 | 备注 |
|---|---|---|---|
| 解析核心 | POST | `/parse/apply` | form-urlencoded，需签名参数 `s` |
| 账号信息 | GET | `/user/info` | 返回**首字母大写**的字段名 |
| 激活 | POST | `/user/auth` | body 为激活码 |
| CDK 兑换 | POST | `/cdk/apply` | |
| 下载代理 | GET | `/xzbs/video_<ts>.mp4?s=<base64>` | 同样需登录 |

响应字段风格不统一：解析接口用**小写** `status/msg/data`，账号接口用**大写** `Code/Msg/Data`。

### 3.3 卡点性质：登录态，不是签名

前端会生成一个签名参数（由前端脚本计算，本仓库不提供实现）。
但关键事实是：**服务端的鉴权中间件先于签名校验**。

差分测试结果——未登录时以下五种情况返回**一字不差**的同一响应：

| 用例 | 结果 |
|---|---|
| 正确签名 | `{"status":403,"msg":"未登录"}` |
| 错误签名（乱填） | 同上，一字不差 |
| 完全不带签名字段 | 同上 |
| 签名字段为空 | 同上 |
| 时间戳过期 | 同上 |

结论：**签名正确性无法通过未登录请求验证**，必须靠与前端脚本逐位比对来确认
（本项目已完成该比对，此处不提供实现）。该 403 在所有镜像与平台子域上一致复现。

### 3.4 登录途径

服务端在返回激活码错误时直接说明了来源：

```
激活码有误，请关注微信公众『考拉解析6』获取
```

页面模态框原文：扫码关注公众号，发送指定文字获取激活码。
这是典型的涨粉漏斗，**不可自动化**，也不应被自动化。

### 3.5 状态语义（排错用）

| 值 | 含义 |
|---|---|
| `0` | 成功（还需返回体内业务码为成功） |
| `1` | 触发人机验证挑战 |
| `201` | 激活码有误 |
| `202` / `203` | 该平台需付费 |
| `205` | 平台已迁移 |
| `403` | 未登录 |

## 5. snapany snapany.com ⚠️（被反爬拦）

- 产品只做下载（本就不含转写）
- 网关存活：`GET /health` → `200 ok`
- 契约端点已还原为 `POST /v1/extract/post`（请求体 `{"link": url}`）与 `/v1/extract/profile`

即使按前端行为带上时间戳、页脚签名、会话标识三个请求头，仍返回
`403 异常请求，请强制刷新当前页后重试`——说明校验发生在服务端且需要浏览器环境
产出的动态凭证。**这不是能靠补头解决的，本项目未纳入。**

## 6. convry convry.com ❌（形态不同）

全量扫描前端分块后，只找到上传/文件类接口（文件上传、临时凭证获取、文件删除）
与一个转换 SDK，**不存在链接解析类入口**。它的工具是上传式的，与本项目

## 7. 傲软 apowersoft.cn（在线版）❌（已停用）

在线版已停用，页面变成了桌面客户端的引流页。**无任何后端可对接。**

### 7.1 判据（静态可证，无需启动浏览器）

| 判据 | 实测结果 |
|---|---|
| 页面自带停机提示 | 中文版「系统维护中，请下载安装桌面端使用」；英文版 `System maintenance, please download and install the desktop version.` |
| 唯一可点动作 | 下载按钮 → 跳转至安装包（macOS 为 `.dmg`） |
| 那个粘贴框是装饰性的 | 不在任何表单内；入口脚本里网络请求调用计数为 **0**（纯弹窗 UI） |
| 框架脚本有无接口 | 只有基础库与登录助手，**无任何下载/解析端点** |
| 疑似 API 域名 | 返回 200，但内容是数年前的占位页，无业务端点 |

它的"API 服务"是商务签约制，没有自助端点——与 snapany「端点已还原、只差签名头」
性质完全不同：**这家没有可逆向的对象**。本项目**不纳入，也不做浏览器兜底**
（浏览器自动化同样只会撞上"请下载桌面端"）。

### 7.2 从这个案例沉淀的通用判断法

判断"某站是否值得继续投入"：

> **先在服务端渲染的可见文案里找停机声明，再看唯一 CTA 是否指向软件安装包。
> 二者同时命中即可判定为引流页，连浏览器都不用开。**

这条方法省下的时间，比它看起来多得多。

## 8. 核验方法备忘

本项目判断一个来源是否可用，按这个顺序：

1. **抓公开首页**，在**服务端渲染**的文案里找停机声明 → 命中则直接判死，不必继续。
2. **找唯一 CTA 的落点**：指向安装包 = 引流页。
3. **看前端脚本有没有网络请求**：入口脚本里请求调用计数为 0，说明页面上的输入框是装饰。
4. **枚举子域**：同一套程序常有平台分域，未部署的子域会返回服务器默认页。
   宣传支持 ≠ 实际部署。
5. **差分测试区分故障类型**：构造"正确参数 / 错误参数 / 缺参数 / 空参数 / 过期参数"
   五组请求。若返回**一字不差**，说明卡点在更前面的中间件（鉴权），
   而不是参数本身——这能立刻告诉你该往哪个方向投入。
6. **对前端脚本做逐位比对**：把自己的实现与站点原始脚本在真实运行时对照输出。
   只有逐位一致，才算真正还原。

来源站的接口与可用性**随时可能变化**。本文一旦与实测不符，以 `--diagnose`
