# 扒稿机 bagaoji

> 视频转文案，链接转原片。**纯标准库、零依赖、零 API Key、零费用。**

把一条视频或笔记链接丢进来，拿回两样东西：

- **① 可编辑的口播文案**
- **② 原片本身** —— 视频 / 音频 / 图文原图 / 封面

这是做自媒体时最高频的重复劳动。扒稿机把它变成一条命令。

```bash
python3 -m bagaoji "https://xhslink.cn/o/xxxxxxxx" --download --out ~/Desktop/扒稿
```

不需要 `pip install` 任何东西，不需要任何平台的 API Key，不产生任何调用费用。

---

## 它解决什么问题

做内容的人每天都在重复同一件事：看到一条值得拆解的作品，先想办法把它保存下来，
再想办法把里面的口播内容变成文字，然后才能开始分析结构、模仿写法、复用选题。

这三步以前要么手工做，要么散落在好几个工具里。扒稿机把它们合并成一条命令：

| 步骤 | 以前 | 现在 |
|---|---|---|
| 拿到原片 | 第三方工具、水印、画质损失 | 一条命令直接落盘 |
| 拿到文案 | 听写、或按分钟付费的转写服务 | 图文笔记直接取正文；视频另配转写 |
| 整理归档 | 手工建文件夹、重命名 | 自动命名、按序落盘、附带元信息 |

**成本对比**：走付费转写服务是按分钟计费的，一条十分钟的视频就要几块钱。
扒稿机**不接入任何计费服务，调用成本为零**。

## 能力边界（先看这个，避免期待错位）

| 能力 | 支持情况 | 说明 |
|---|---|---|
| 小红书图文笔记正文 | ✅ **开箱可用** | 从笔记数据里直接取正文，**不需要排队、不消耗任何额度** |
| 小红书图集原图 | ✅ **开箱可用** | 支持原始画质 / 统一 JPEG / WebP 三档 |
| 小红书视频 | ✅ **开箱可用** | 识别多清晰度，可选只下第一路 |
| 封面、互动数据、元信息 | ✅ **开箱可用** | 点赞 / 收藏 / 评论 / 分享、作者、标题 |
| 其他平台 | ⚠️ **需自行接入** | 公开包只内置小红书适配器，接入方式见 `docs/extending.md` |
| 视频语音转文字（ASR） | ❌ **不含** | 刻意不内置，以保证「零依赖、零 API Key、零费用」成立 |

两句话总结：

- **能**：小红书全家桶 —— 文案、图集、视频，开箱即用。
- **不能**：其他平台开箱即用；视频自动转文字。

## 快速开始

### 环境要求

- **Python 3.9 或更高**（系统自带即可）
- **无需 `pip install` 任何东西** —— 全部使用标准库

> macOS / Linux 用 `python3`；**Windows 用 `python`**（Windows 上没有 `python3` 这个命令）。

### 基本用法

```bash
# ① 只要文案与元信息（默认行为）
python3 -m bagaoji "https://xhslink.cn/o/xxxxxxxx"

# ② 连原片一起下载到指定目录
python3 -m bagaoji --download --out ~/Desktop/扒稿 "https://xhslink.cn/o/xxxxxxxx"

# ③ 只要图集原图，且要最高画质
python3 -m bagaoji --download --only image --img-mode raw "https://xhslink.cn/o/xxxxxxxx"

# ④ 结构化输出，便于二次处理
python3 -m bagaoji --json "https://xhslink.cn/o/xxxxxxxx"

# ⑤ 查看已注册的来源适配器
python3 -m bagaoji --list
```

### 参数速查

| 参数 | 作用 |
|---|---|
| `--mode {text,parse,both}` | `text`=只要文案（默认）/ `parse`=只要元信息与直链 / `both`=都要 |
| `--download` | 把媒体实际下载到本地 |
| `--only {video,audio,image}` | 只下载某一种媒体 |
| `--img-mode {jpg,raw,webp}` | 图片质量：`jpg`=统一 JPEG（默认）/ `raw`=原始最大 / `webp`=最小 |
| `--out DIR` | 每条结果存为 Markdown，媒体落在同目录 |
| `--media-dir DIR` | 媒体落盘目录（默认同 `--out`） |
| `--workers N` | 图集并发线程数（默认 4） |
| `--all-videos` | 下载全部视频编码变体（默认只下第一路） |
| `--cookie STR` / `--cookie-file PATH` | 携带登录态（见下节） |
| `--json` | 结构化输出 |
| `--list` | 列出已注册适配器 |
| `--auth` | 查看登录态说明与本地已读到的凭据来源 |
| `--version` | 版本号 |

### 批量与自动化

```bash
# 多条链接一次处理
python3 -m bagaoji --json "链接1" "链接2" "链接3"

# 从标准输入读入（每行一条）
cat links.txt | python3 -m bagaoji --download --out ~/Desktop/扒稿
```

程序会**自动从整段分享口令中抽取链接**，所以直接粘贴 App 里复制的整段文字即可。

## 输出说明

- **默认**：把结果打印到终端（标题 + 互动数据 + 文案 + 直链 + 文件路径）
- **`--out DIR`**：写成 Markdown 文件，媒体落盘同目录，图集按 `_图01`、`_图02` 顺序命名
- **`--json`**：结构化结果，关键字段如下

| 字段 | 含义 |
|---|---|
| `ok` | 是否解析成功 |
| `platform` / `platform_label` | 来源标识与中文名 |
| `work_type` | 作品类型（图文 / 视频） |
| `title` | 标题 |
| `transcript` | 正文或口播文案 |
| `video_streams` | 视频直链列表（含清晰度、体积） |
| `image_urls` | 图集直链列表 |
| `error` | 失败原因（成功时为空） |

## 链接怎么拿（最容易翻车的一步）

1. 在 App 里点笔记右上角的「**分享 → 复制链接**」
2. 直接粘贴整段分享口令即可，程序会自动抽出其中的链接
3. ⚠️ **不要手动删掉链接里 `?` 后面的参数**

第 3 条值得单独强调：分享链接里带有一个必要的访问参数，**手动删掉后页面会返回一个空壳**，
而且**没有任何报错提示** —— 表现为「解析不出来但也不说为什么」。这是实际使用中最高频的失败原因。

## 登录后更好用：关于 Cookie

扒稿机**不需要登录就能用**。但在下面两种情况下，带上你自己的登录态会明显更稳：

| 情况 | 说明 |
|---|---|
| **被风控拦截** | 平台偶尔对高频访问返回空页或验证页，带上登录态可显著降低概率 |
| **需要更高额度** | 部分来源对未登录访问有更严格的频次限制 |

### 怎么取 Cookie

1. 在电脑浏览器里打开目标站点并**登录你自己的账号**
2. 按 `F12` 打开开发者工具，切到 **Console（控制台）** 标签
3. 输入 `copy(document.cookie)` 回车 —— Cookie 已被复制到剪贴板
4. 回到终端，用下面任意一种方式传入

> 若控制台提示粘贴限制，需先在输入框敲 `allow pasting` 回车确认。

### 四种传入方式（优先级从高到低）

```bash
# ① 命令行参数（仅本次生效）
python3 -m bagaoji --cookie "a=1; b=2" "链接"

# ② 从文件读取（支持 JSON 与纯文本两种格式）
python3 -m bagaoji --cookie-file ~/cookies.json "链接"

# ③ 环境变量（按适配器名区分，通用兜底）
export BAGAOJI_COOKIE="a=1; b=2"
export BAGAOJI_COOKIE_XHS="专供小红书的一份"

# ④ 固定存放（推荐，一次配好长期可用）
#    ~/.bagaoji/cookies.json   {"_default": "...", "xhs": "..."}
#    ~/.bagaoji/cookies.txt    name<TAB>cookie
```

跑 `python3 -m bagaoji --auth` 可以查看当前已从哪些本地来源读到了凭据
（**只显示长度和 Cookie 名，绝不回显内容**）。

### 三条安全提醒

1. **Cookie 等同于密码** —— 拿到它就等于拿到了你的登录态，不要发给任何人
2. **过期了先重新取一次** —— 九成的「以前能用现在不行」都是 Cookie 过期
3. **只用自己的账号** —— 不要使用他人的凭据

> 本项目**不内置、不获取、不共享、不上传**任何凭据，也**不提供自动登录或验证码规避**。
> 所有登录态都由使用者自行提供、自行保管。

## 接入你自己的来源

公开包只内置小红书适配器。其他来源是**插件式**接入的，**不需要修改本项目的代码**：

```bash
# 把你的适配器脚本放进这个目录
mkdir -p ~/.bagaoji/adapters
cp your_source.py ~/.bagaoji/adapters/

# 启动时会自动加载
python3 -m bagaoji --list

# 指定适配器解析
python3 -m bagaoji --engine mysource "链接"
```

完整的适配器契约、加载机制、登录态接入方式、数据模型与自检清单，见
[`docs/extending.md`](docs/extending.md) —— 并附有一个可直接改用的模板
`examples/custom_adapter_template.py`。

## 设计要点

1. **零依赖** —— 只用 Python 标准库。没有 `pip install`，没有版本冲突，没有虚拟环境
2. **零密钥** —— 不接入任何需要 API Key 的服务，因此也不产生任何费用
3. **适配器制** —— 每个来源站是一个独立适配器，可插拔、可自行扩展
4. **下载健壮性** —— 按响应头反推扩展名（不靠猜）、失败退避重试、图集并发下载
5. **诚实失败** —— 解析不出来就明确报错并指出原因，不返回看似成功的空结果

## 合规与使用边界

**本项目做什么**

- 只处理**公开可访问**的内容
- 结果用于学习、拆解与创作参考

**本项目不做什么**

- 不绕过任何平台的付费墙、登录限制或人机验证
- 不破解、不代持账号、不做批量抓取
- 不缓存、不长期分发平台签发的媒体直链

**你需要自己负责的部分**

- 遵守各来源站的服务条款与 robots 约定
- 尊重原作者版权；二次创作与商用前自行确认授权
- 控制请求频率，避免给平台造成压力
