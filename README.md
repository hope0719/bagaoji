# 扒稿机 bagaoji

> 视频转文案，链接转原片。**纯标准库、零依赖、零 API Key、零费用。**

把一条视频或笔记链接丢进来，拿回两样东西：

- **① 可编辑的口播文案**
- **② 原片本身** —— 视频 / 音频 / 图文原图 / 封面

这是做自媒体时最高频的重复劳动。扒稿机把它变成一条命令。

```bash
python3 -m bagaoji "https://xhslink.cn/o/xxxxxxxx" --download --out ~/Desktop/扒稿
```

不需要 `pip install` 任何东西，不需要任何平台的 API Key，不产生任何调用费用。

## 它解决什么问题

做短视频拆解、仿写、二次创作时，前面永远卡着两步机械劳动：

1. 把视频里的口播抄成文字 → 手动听打，10 分钟的视频要花 40 分钟；
2. 把原片存到本地 → 平台不给下载按钮，或者下下来带水印。

常见的做法是调云端语音转写 API（按分钟计费，还要申请 Key、管额度、传文件），
或者用在线解析站（要注册、要登录、一天限几条）。

扒稿机换了个思路：**把解析站自己的公开接口当作可编程入口**，
所有能力都收敛到本地一条命令里，不引入任何外部服务的账号与费用。

## 能力边界（先看这个，避免期待错位）

本仓库采用**分层开源**：公开层交付可运行的通用能力，来源站的具体接入由你按需补全。

| | 本仓库公开层 | 说明 |
|---|---|---|
| 小红书链接解析 | ✅ **已实现** | 短链 / 完整链接 / 整段分享口令均可 |
| 小红书图文笔记正文 | ✅ **直接取出** | 不排队、不消耗额度、不经过任何转写服务 |
| 小红书图集原图 | ✅ **批量下载** | 无签名原图直链，三档画质可选，并发落盘 |
| 小红书视频原片 | ✅ **可下载** | 多清晰度可选，自动跳过重复编码变体 |
| 抖音 / B站 / 快手 / 视频号 / YouTube / TikTok 等 | ⚠️ **需自建适配器** | 接入方式见 [docs/extending.md](docs/extending.md) |
| 视频语音转文字（ASR） | ❌ **不含** | 公开层刻意不内置任何转写服务，避免引入 API Key 与费用 |
| 需要登录才完整的来源 | ✅ **支持自带 Cookie** | `--cookie` / `--cookie-file` / `BAGAOJI_COOKIE` / `~/.bagaoji/cookies.json`；本项目不内置也不上传任何凭据，见[下一节](#登录后更好用关于-cookie) |
| 站点可用性公示与自检 | ✅ **`--diagnose`** | 一条命令刷新各来源站的当前状态 |

两句话总结：

- **能**：小红书全家桶（文案 + 图集 + 视频），开箱即用；需要登录的来源，带上你自己的 Cookie 即可用。
- **不能**：其他平台开箱即用；视频自动转文字；替你注册或获取账号。

如果你要的是"任何平台都一键出逐字稿"，本仓库不承诺这个——
但 `docs/extending.md` 给了接入路径，且 [信息源公示](#信息源公示) 会告诉你哪些来源当前真的可用。

## 快速开始

**要求：Python 3.9+。没有别的依赖。**

```bash
git clone https://github.com/hope0719/bagaoji.git
cd bagaoji

# ① 取文案（图文笔记直接拿正文，视频笔记提示需自行转写）
python3 -m bagaoji "https://xhslink.cn/o/xxxxxxxx"

# ② 解析 + 下载素材到本地
python3 -m bagaoji --download "https://xhslink.cn/o/xxxxxxxx" --out ~/Desktop/扒稿

# ③ 只要最高画质原图
python3 -m bagaoji --download --only image --img-mode raw "https://xhslink.cn/o/xxxxxxxx"

# ④ 顺手看一眼各来源站现在还能不能用
python3 -m bagaoji --diagnose

# ⑤ 看已加载的适配器
python3 -m bagaoji --list

# ⑥ 需要登录的来源：带上你自己的 Cookie（详见下文）
python3 -m bagaoji --cookie "a=1; b=2" "https://<需要登录的来源>/xxxx"
python3 -m bagaoji --auth            # 先看哪些来源需要登录、怎么取 Cookie
```

也可以装成命令行工具：

```bash
pipx install .        # 或 pip install .
bagaoji "https://xhslink.cn/o/xxxxxxxx"
```

### 作为库使用

```python
import bagaoji

r = bagaoji.parse("https://xhslink.cn/o/xxxxxxxx")
if r.ok:
    print(r.title, r.author, len(r.image_items))
    print(r.transcript)                       # 图文笔记 = 正文原文
    for item in r.image_items:
        print(item.width, item.height, item.url)
```

完整示例见 [`examples/parse_and_download.py`](examples/parse_and_download.py)。

### 命令速查

| 参数 | 作用 |
|---|---|
| `--mode parse\|text\|both` | 只要直链 / 只要文案（默认）/ 都要 |
| `--download` | 把媒体实际下载到本地 |
| `--only video\|audio\|image` | 只下载某一种媒体 |
| `--img-mode jpg\|raw\|webp` | 图片画质：统一 JPEG（默认）/ 原始文件 / 最小体积 |
| `--workers 4` | 图集并发线程数 |
| `--all-videos` | 下载全部视频编码变体（默认只下第一路） |
| `--out DIR` | 每条结果保存成 Markdown，媒体落在同目录 |
| `--cookie STR` | 本次调用使用的登录态 Cookie（`"a=1; b=2"`） |
| `--cookie-file PATH` | 从文件读 Cookie（JSON 映射表或纯文本） |
| `--auth` | 查看哪些来源需要登录、怎么取 Cookie、当前已读到哪些凭据 |
| `--json` | 结构化输出 |
| `--engine NAME` | 强制指定适配器（对照排错） |
| `--diagnose` | 刷新站点可用性公示 |
| `--list` | 列出已注册适配器 |

也支持**整段分享口令**（自动抽链）、**多条链接批量**、以及从 **stdin** 读入：

```bash
cat urls.txt | python3 -m bagaoji --download
```

## 设计要点

这几个点都是踩过坑之后定下来的，改动前请先读原因。

### 1. 为什么小红书要单独一条通道

通用解析站对小红书常常只做到"拿到图"，但拼出来的图片直链会**丢掉图床的 OSS 路径前缀**（如 `oss-ae/`），实测直接 404：

```
别处给的：   https://sns-img-hw.xhscdn.com/notes_pre_post/1040g3v8...    -> 404
笔记页里的：  oss-ae/notes_pre_post/1040g3v8...                            -> 200
```

而这个前缀**因笔记而异**（实测两篇笔记一有一无），无法靠猜补全，必须从笔记页取原始 `fileId`。
因此小红书走独立通道：短链 → token → 笔记页 → 内嵌 JSON。

### 2. 三条硬性约束（小红书）

1. **`xsec_token` 是硬性必需**，不是统计参数。删掉后请求同一篇笔记只会返回空骨架页
   （不同笔记 ID 的页面字节数完全一致），笔记数据键根本不存在。
   → 必须用 App 里「分享 → 复制链接」得到的链接，不要手动删问号后的参数。
2. **短链有 4 个域名**：`xhslink.com` / `xhslink.cn` / `xhsurl.com` / `xhsurl.cn`。
   只识别 `.com` 会让 `.cn` **静默失败**——返回 200 但没有任何内容。四个都已覆盖。
3. **必须用移动端 UA**。桌面 UA 拿到的 HTML 里不含笔记数据，这是最常见的翻车点。

### 3. 图片直链不要签名

`fileId` 直接拼图床域名即可，**长期有效**；页面上那些带签名的临时地址
（形如 `sns-webpic-qc.xhscdn.com/{时间}/{md5}/...`）反而会过期，只作兜底。

同一张 1242×1660 实测：`raw` 823 KB / `jpg` 88 KB / `webp` 53 KB。

### 4. 下载器的三个细节

- **按响应头 `Content-Type` 反推扩展名**：有些代理直链 URL 上没有扩展名，
  按 URL 猜会得到假的 `.mp4`（实际是 WebM）。
- **退避重试 + 备用域名切换**：CDN 会偶发 403/5xx，而签名本身往往还有效
  （实测同一签名 URL 前一次被拒、紧接着重试即成功）。只有 403/408/429/5xx
  与网络错误才重试；404 这类确定性错误重试无意义。
- **图集并发、视频串行**：图集常见 9~18 张，并发收益明显；视频体积大，串行避免抢带宽。
  视频默认只下第一路——同一分辨率常同时给 h264/h265 两个编码变体，全下等于白拉一倍体积。

## 登录后更好用：关于 Cookie

**这一节很重要，请务必读完——它会直接决定你能不能把这个工具用起来。**

我们调查过的来源站里，有相当一部分的问题**不是技术不通，而是没有登录态**：
接口形态完整、逻辑清晰，唯一的拦路虎是服务端在鉴权层统一返回「未登录」。
这类站点只要你在浏览器里**正常登录一次、把 Cookie 交给本工具**，就能打通。

按登录态的影响，来源分成三类：

| 类别 | 含义 | 例子 |
|---|---|---|
| **登录后才可用** | 免登录时被统一拦在鉴权层，登录即恢复 | 考拉解析、下载狗 |
| **登录后更好用** | 免登录就能用，但登录后额度更高 / 画质更高 / 平台更多 | 抖虫（转写额度）、多数解析站 |
| **登录与否无差别** | 本来就是公开路径 | 本仓库内置的小红书专线 |

### 怎么取 Cookie（通用步骤，与具体站点无关）

1. 浏览器打开该来源站，**按它自己的流程正常登录**（扫码 / 手机号 / 激活码都行）；
2. 确认页面已是登录状态（能看到自己的账号，或不再提示登录）；
3. 打开开发者工具 → **网络** 面板 → 刷新页面 → 点任意一个本站请求；
4. 在**请求标头**里找到 `Cookie` 一行，整行复制（形如 `a=1; b=2; c=3`）；
   也可以在控制台直接执行 `copy(document.cookie)` 一键复制。
5. 交给 bagaoji —— 四种方式任选：

```bash
# ① 单次命令传入（最直接）
python3 -m bagaoji --cookie "a=1; b=2" "https://<来源站>/xxxx"

# ② 从文件读（适合较长的 Cookie）
python3 -m bagaoji --cookie-file ~/my_cookie.txt "https://<来源站>/xxxx"

# ③ 环境变量（一次设置，当前终端会话内一直有效）
export BAGAOJI_COOKIE="a=1; b=2"
python3 -m bagaoji "https://<来源站>/xxxx"

# ④ 长期配置文件（推荐，写完不用再管）
mkdir -p ~/.bagaoji
echo '{"_default": "a=1; b=2"}' > ~/.bagaoji/cookies.json
```

优先级（高 → 低）：`--cookie` → `--cookie-file` → `BAGAOJI_COOKIE_<适配器名>` →
`BAGAOJI_COOKIE` → `~/.bagaoji/cookies.json` → `~/.bagaoji/cookies.txt`。
多个来源的凭据可以共存，按适配器名区分：

```json
// ~/.bagaoji/cookies.json
{
  "_default": "留给没有单独配置的来源",
  "kaolajiexi": "该来源专用的 Cookie",
  "xzgtool": "另一个来源专用的 Cookie"
}
```

随时用 `python3 -m bagaoji --auth` 查看**当前从哪些本地来源读到了凭据**——
它只显示字符数和 Cookie 名，**不会回显凭据内容**。

### 三条必须记住的提醒

- **Cookie 等同于你的登录凭证。** 不要提交进 git、不要贴进 issue、不要发给别人。
  本项目不上传它、不写进日志、不放进任何输出。
- **Cookie 会过期**（几小时到几个月都有）。用到一半突然又提示未登录，
  **先重新复制一份，再怀疑别的**——九成是这个问题。
- **请使用你自己的账号**，并遵守该站点的服务条款。本项目不提供任何代持账号、
  共享账号或绕过登录限制的手段；把账号态交给第三方工具使用是否被站点允许，
  需要你自己判断与承担。

### 什么样的站点最值得投

按有用程度排序，供你判断：

1. **有「贴链接 → 出结果」的形态** —— 这是本项目能接入的前提；
2. **免登录可用，或注册即可用** —— 门槛越低，能帮到的人越多；
3. **长期稳定运行** —— 比功能多更重要；
4. 单平台也行 —— 一个稳定的 B 站解析站，比一个宣称支持百站但全挂的站有用得多。

以下这些**不用投**，投了也接不进来（原因见[信息源公示](#信息源公示)）：

- 只能**上传文件**、没有链接解析入口的；
- 页面上的「API 服务」需要**商务签约**、没有自助端点的；
- 在线版**已经停用**、只剩桌面客户端下载按钮的。

### 收到投稿后我会做什么

1. 按 [docs/sites.md §8](docs/sites.md#8-核验方法备忘) 的流程**实测核验**，
   而不是照抄宣传文案；
2. 把结论写进公示表——**能用就写能用，不能用就写清卡在哪一步**，
   包括"卡在登录""卡在服务端签名""形态不符"这些不好看但有用的结论；
3. 形态匹配且合规风险可控的，补一个适配器；
4. 投稿人会在 `docs/sites.md` 里署名（你愿意的话）。

> 一条原则：**这个项目的价值不在"支持多少站点"，而在"公布哪些站点真的能用"。**
> 所以更欢迎你告诉我"某个站已经废了"——这比多一个宣称支持的站点有用得多。

## 接入你自己的来源

分层开源的设计意图是：**通用能力开源，来源接入自持。**

所有来源都是适配器。把自建适配器放进 `~/.bagaoji/adapters/`，启动时会自动加载，
**不需要 fork 本仓库**：

```python
# ~/.bagaoji/adapters/my_source.py
from bagaoji.adapters.base import Adapter
from bagaoji.models import MediaResult

class MyAdapter(Adapter):
    name = "mysource"
    label = "我的来源"
    domains = ("example.com",)
    login_free = True
    note = "一句话说明"

    def parse(self, url, **opts):
        res = MediaResult(input_url=url, platform=self.name, platform_label=self.label)
        # ... 你的解析逻辑 ...
        res.ok, res.title, res.transcript = True, "...", "..."
        return res

ADAPTER = MyAdapter()
```

```bash
python3 -m bagaoji --list                      # 确认已加载
python3 -m bagaoji --engine mysource "<链接>"   # 指定适配器解析
```

### 需要登录的来源：一行拿到 Cookie

如果你的来源需要登录态，**不要在适配器里自己读环境变量或文件**——
统一调用基类提供的方法，凭据来源才可审计、可脱敏：

```python
class MyAdapter(Adapter):
    name = "mysource"
    label = "我的来源"
    domains = ("example.com",)
    login_free = False                                   # ← 如实声明，会显示在 --list
    auth_hint = "登录后额度更高"                           # ← 登录态收益，一句话

    def parse(self, url, **opts):
        cookie = self.cookie(**opts)                     # ← 一行拿到凭据，取不到为 None
        if cookie is None:
            return MediaResult(input_url=url,
                               error="该来源需要登录态，请用 --cookie 传入或写入 "
                                     "~/.bagaoji/cookies.json")
        # ... 后续请求带上 cookie ...
```

这样写完之后，用户端四种凭据传入方式（`--cookie` / `--cookie-file` / 环境变量 /
`~/.bagaoji/cookies.*`）**全部自动生效**，你不需要额外做任何事；
`bagaoji --auth` 也会自动把你的 `auth_hint` 列出来。

接口形态（各来源的端点、字段名、鉴权方式）见 [docs/extending.md](docs/extending.md)。
注意：**该文档只描述接口形态，不含任何加密实现或密钥。**
写好了愿意开源进来，欢迎按[投稿](#欢迎投稿把你手里的同类站点交出来)方式提交。

## 合规与使用边界

使用本项目前，请确认你理解并接受以下边界。

**本项目做什么**

- 只处理**公开可访问**的内容。
- 只读取公开页面与公开接口返回的数据。
- 结果供学习、拆解与创作参考。

**本项目不做什么**

- **不含**任何绕过付费墙、登录限制或人机验证的实现。
- **不含**任何破解、代持账号或批量抓取的功能。
- **不含**任何账号凭据：不内置、不获取、不共享、不上传 Cookie（登录态一律由你本人提供）。
- 不缓存、不长期分发平台签发的媒体直链。

**你需要自己负责的部分**

- **登录态由你自持**：Cookie 是你自己的账号凭证，请自行保管，勿提交进仓库或对外分享；
  把账号态交给第三方工具使用是否符合该站点规则，需你自行判断。
- 遵守各来源站的**服务条款**与 robots 约定；本项目不对第三方站点的授权状态作任何声明。
- 遵守**著作权与平台规则**；提取结果用于商用、搬运或二次发布前，请自行确认权利归属。
- 控制**请求频率**，避免给来源站造成压力。
- 媒体直链**有时效**（数小时至数天），需要留存请实际落盘；**不要**把直链写入缓存或对外分发。
- 提取到的文案用于仿写/二创时，需自行规避平台的搬运规则。

**关于逆向记录的口径**

各来源站的接口形态来自对**公开前端页面**的分析与真实验证。本仓库公开层
**不发布**任何具体的加密密钥、签名实现或替换方法；需要那部分内容的，
请自行评估合规风险后实现，或参考 [docs/extending.md](docs/extending.md) 的形态说明。
